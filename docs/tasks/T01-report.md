### Scene parameters (as pinned by the brief)

Camera `fov 45 / near 0.1 / far 200` at `(16,14,16)` looking at origin; OrbitControls with
damping 0.08, pan off, distance 10–45, `maxPolarAngle 1.35`. `Fog(palette.fog, 30, 95)`;
`HemisphereLight(ambientSky, ambientGround, 0.8)`; `DirectionalLight(sun, 1.6)` at
`(18,26,10)`, shadow camera ±30, `mapSize 2048`. Ground = `CircleGeometry(60)` rotated flat,
`MeshLambertMaterial(grass)`, receives shadow. Placeholder trees share one cylinder + one cone
geometry and two foliage materials; bushes share one squashed sphere; campfire is a torus
stone ring + `MeshBasicMaterial` flame cone. Pixel ratio `Math.min(devicePixelRatio, 2)`.

## 3. Deviations from the brief (with reasons)

- **D1 — added `@types/three` as a devDependency.** three `0.186.1` ships **zero** `.d.ts`
  files (verified: `find node_modules/three -name '*.d.ts'` → 0, and no `types` field in any
  checked version). Without it, `import * as THREE from 'three'` fails strict TS with TS7016
  and the scene degrades to implicit `any`, which acceptance criterion 2 forbids. It is
  types-only, ships no runtime code. Every other dependency is exactly the listed set.
- **D2 — versions pinned to current releases** (three 0.186, vite 8, vitest 5, typescript 7)
  rather than older majors; the brief named the packages, not versions.
- **D3 — the task popover lives inside `#villager-panel`** (absolutely positioned over the
  panel, anchored to the clicked card) instead of being a third sibling of the panel. Still
  exactly three zones, and the brief's "anchored near the panel" is satisfied while staying
  reachable for keyboard and click-outside handling.
- **D4 — added an inline SVG data-URI favicon** in `index.html`. Without it the browser's
  automatic `/favicon.ico` request 404s and prints a console *error*, which would violate the
  "zero console errors" criterion. It is inline, so no external asset is introduced.
- **D5 — critical shell CSS (body margin/overflow, canvas sizing) lives in a small inline
  `<style>` in `index.html`** instead of `ui.css`, so the first paint is not a white flash.
  `ui.css` still owns all cozy styling; `tokens.css` remains exactly the DESIGN §4 properties.
- **D6 — `box-sizing: border-box` inside `#ui`**, so the declared `width: 250px` villager panel
  measures 250px in the browser instead of 250 + padding.
- **D7 — `src/sim/**` written by T01.** DESIGN §5 assigns `src/sim/**` to T2, but the T01 brief
  explicitly requires the stub (`types.ts`, `index.ts`, `index.test.ts`) and T2 needs the
  contract to build against. Flagging for the orchestrator: treat these three files as T2's
  starting point (it should extend rather than re-create them).

## 4. Known gaps / concerns

- **G1 — `PCFSoftShadowMap` is removed in three 0.186.** The brief pins
  `shadowMap.type = THREE.PCFSoftShadowMap`; three now logs
  `THREE.WebGLShadowMap: PCFSoftShadowMap has been removed. Using PCFShadowMap instead.`
  (a warning, not an error — criterion 3 still holds). I kept the pinned value and commented it
  in `src/render/index.ts` rather than silently deviating. One-line fix if the orchestrator
  prefers a clean console: use `THREE.PCFShadowMap` (visually identical here, since three falls
  back to it anyway) or pin three below the removal. T3 owns the final lighting setup.
- **G2 — the popover covers the neighbouring cards**, so the selected villager's own
  `.task-label` is hidden while the popover is open. Cosmetic; T5 may want to offset it.
- **G3 — placeholder world only.** Trees/bushes/campfire are shared-geometry meshes from
  `state.nodes` with no ambient motion; T3 replaces them with `InstancedMesh`, T4 adds villagers
  (so the 8 villagers currently have no 3D representation, by design for T01).
- **G4 — `tick()` is a no-op**, so the render loop redraws an identical scene each frame and
  `window.__cozy.getState().tick` stays 0. Expected until T2.
- **G5 — bundle size warning.** `vite build` prints the standard "chunks are larger than 500 kB"
  notice (563.95 kB, mostly three). Expected for a three.js app; no action taken since code
  splitting is not in T01 scope.
- **G6 — pixel ratio is read once at init**, so a mid-session change to `devicePixelRatio` (e.g.
  dragging the window to another display) keeps the old ratio until reload. Aspect stays correct.
