# B7 — UI: fuel pill, task grid, structure cards, reset, labels

Fits: batch 2's player-facing surface — all inside the existing three zones (DESIGN §6). Read §6 and
§3 (`UIActions`, `UIHandle`) first; the contracts already carry `build`, `resetVillage`,
`selectStructure`, `pickStructure`.

## Deliverable

1. **HUD (`src/ui/index.ts`, `src/styles/ui.css`)** — third pill `[data-res="fuel"]`: flame icon,
   value, and a mini bar (`width = fuel/max %`); a data-state class (`roaring|steady|dim|embers`) for a
   subtle colour shift. Compact — no layout break.
2. **Task grid** — the popover's task buttons become a 2×3 grid: Chop wood · Gather berries · Rest ·
   Tend fire · Cook · Stop. Disabled states: Cook needs the pot built; Stop disabled when the selected
   villager is idle; everything else enabled.
3. **Structure cards** — `selectStructure(id)`: the same popover shows the structure: name; if unbuilt:
   cost line (icons + amounts) + a Build button `[data-build]` (disabled when unaffordable, with the
   shortfall visible); if built: status line (pot → "Meals: N" · garden → "Growing…" · others → "Built").
   Build → `actions.build(id)`; the card refreshes from state.
4. **Reset** — small `#hud .reset-btn` (⟲): first click arms it ("Sure?" label, 3 s window), second
   click calls `actions.resetVillage()`. No modals.
5. **Card labels** — while walking keep `Walking…`; working shows the task (`Chop wood`, `Gather
   berries`, `Tending fire`, `Cooking`); resting `Resting`; idle `Idle`.
6. **`src/main.ts` wiring** — canvas click order: villager first, then structure, else clear both;
   actions: `build: (id) => buildStructure(state, id)`, `resetVillage: () => { clearSave(); location.reload(); }`.
