# T07 — Final independent review + curated improvement proposals

Fits: all features (T1–T6) are validated individually. Before the first human playtest, a fresh
model reviews the whole slice for defects, and proposes improvements so the orchestrator can curate
the next batch with the user.

**This is a review + proposal task. You may create ONLY `docs/tasks/T07-report.md`. Do not modify
any source file, config, or other document. Do not commit. Do not dispatch subagents.**

## Part A — Final review (read-only)

Read `DESIGN.md` (binding spec: feel pillars, contracts, simulation rules, anti-bloat rules) and the
whole `src/` tree. Review the completed slice for:

1. **Correctness / bugs** — logic errors, edge cases, NaN/divide-by-zero, state desync between sim,
   render, UI, audio; resource accounting; event handling; anything that breaks after long play
   (hours) or extreme input.
2. **Contract violations** — anything that contradicts DESIGN §3/§3.1 (exact numbers, signatures,
   additive-only evolution, determinism rules).
3. **Feel / anti-bloat** — anything that fights DESIGN §2 (cozy, gentle, sparing) or §6 (3 UI zones,
   no bloat); perf traps that would breach ~200 draw calls or 600k triangles as the world grows.
4. **Dead code / leftovers** — unused exports, stale comments, duplicated magic numbers that belong
   in one place.

Output format in the report: findings ranked **Critical / Important / Minor**, each with
`file:line`, what's wrong, why it matters, and a suggested minimal fix. Be concrete. If a section is
clean, say so explicitly. Cap: 12 findings, best first. No style nitpicks below Minor.

## Part B — Improvement proposals (20)

Propose **20 improvements** for the game, from a player's perspective (not refactors). Mix:
- cozy/feel polish (animation, ambient, audio, UI warmth)
- gameplay depth consistent with slice-1 scope (villagers, tasks, resources)
- quality-of-life (camera, selection, feedback)
- performance/robustness only where it serves the player experience

Order them roughly by implementation difficulty within your list, and mark each
`[easy] / [medium] / [hard]`. Two or three sentences each: what it is, why it makes the game better.
Everything must respect DESIGN §2 and §6 (no UI bloat; additions fold into the three existing zones).

## Report contract

Write everything to `docs/tasks/T07-report.md`. Reply with only: status, your chosen
report path, the count of Critical/Important findings, and one line on the most serious finding.
