# T02 — Pure sim core: villager FSM, tasks, resources, seeded RNG (+ unit tests)

Fits: T1 delivered the shell and UI with stub behavior. T02 makes the simulation real so the
village actually works when T5 wires it up. It is fully unit-testable — that is the point.

Read `DESIGN.md` §3 and **§3.1 (binding numbers)** plus §2 (feel pillars) first. This brief adds
the exact deliverables.

## Deliverable

Replace the stub internals of `src/sim/` with the real simulation. Public signatures from
DESIGN §3 (including `facing`, `events`, `SimEvent`) are the contract and must not change;
additional internal modules are encouraged. Suggested layout:

- `src/sim/rng.ts` — `mulberry32(seed): () => number` (the seed lives in the state).
- `src/sim/world.ts` — node generation: 1 campfire at origin, 40 trees + 20 bushes scattered in
  an annulus r=6…28 (same approach as T1's stub: rejection sampling with min gap 1.8, 12 tries).
  Node ids `tree-1…tree-40`, `bush-1…bush-20`, `campfire`.
- `src/sim/villagers.ts` — the fixed 8-name roster and spawn ring (as T1).
- `src/sim/tasks.ts` — task → node kind mapping, nearest-node lookup (squared distance, ties by id
  ascending), numeric constants from DESIGN §3.1.
- `src/sim/index.ts` — `createInitialState`, `assignTask`, `tick` per DESIGN §3.1, plus re-exports.

Behavior requirements (exact, from DESIGN §3.1):

1. `createInitialState(seed = 1)`: deterministic; `tick: 0`, `events: []`,
   resources at 0, all villagers `idle`, `task: null`, `targetNodeId: null`, `facing: 0`.
2. `assignTask(state, id, task)`: sets `task`; then (unless null) nearest target of the mapped
   kind → `state: 'walking'`. `null` → `idle`, target cleared. Unknown villager id → no-op.
3. `tick(state, dtMs)`: `tick += 1`; clears `events`; then per villager:
   - `walking`: move toward target at 2.2 u/s (dt-scaled), update `facing = atan2(dx, dz)`;
     on distance ≤ 0.45 → `arrived` event; `rest` → `resting`, others → `working`.
   - `working`: accumulate work time, each 1400 ms → one `chop` or `gather` event + resource +1.
   - `resting`: after 4000 ms → `idle`, `task = null`, target cleared, one `rest-done` event.
   - `idle`: nothing.
   - `dtMs = 0` is legal and changes nothing. Never produce NaN.
4. No `Math.random`, no `Date`, no timers, no DOM/three imports inside `src/sim/`.

## Tests (replace `src/sim/index.test.ts`; delete it once superseded)

Create `src/sim/rng.test.ts` and `src/sim/sim.test.ts` covering at least:

1. RNG: same seed → same sequence; different seeds differ.
2. `createInitialState` is deterministic (two calls deep-equal) and has the fixed shape:
   8 villagers, ids `v1…v8`, roster names/hat colors in order, 61 nodes, counters 0.
3. `assignTask('chop')` → `walking`, `targetNodeId` is the nearest tree (verify by recomputing).
4. Walk→work: with a 100 ms-step helper, the villager reaches the node, becomes `working`, and
   after 1400 ms of work wood is +1 (and after 2800 ms it is +2). Same for berries.
5. `rest`: arrives → `resting`; after 4000 ms → `idle`, task null, one `rest-done` event.
6. Events lifecycle: a tick that yields contains `{type:'chop'|'gather', villagerId}`; the next
   tick clears `events` before appending.
7. Reassigning mid-walk retargets (new `targetNodeId`, still `walking`); `assignTask(null)` stops.
8. `tick(state, 0)` is a safe no-op (no NaN, positions unchanged).
9. Determinism end-to-end: two fresh states + identical tick/assign sequences stay deep-equal.

Tests must assert real values (no empty assertions); use a small `run(state, totalMs, stepMs)` helper.
